## 2. Gap Analysis

### 2.1 Controller Bugs

**LLMActiveModelController — broken watch handlers** (`llmactivemodel_controller.go:484-491`)

The map functions enqueue the *watched object's own* NamespacedName as a reconcile request:

```go
Watches(&cogitodevv1alpha1.LLMModel{}, handler.EnqueueRequestsFromMapFunc(func(ctx context.Context, obj client.Object) []ctrl.Request {
    return []ctrl.Request{{NamespacedName: client.ObjectKeyFromObject(obj)}}
}))
```

This tries to reconcile an `LLMModel` as if it were an `LLMActiveModel` — the request will always be NotFound and silently dropped. The correct behavior: when any `LLMModel` or `LLMBackend` changes, find the singleton `LLMActiveModel` in the same namespace and enqueue *that*.

**LLMModelOverlayController — O(n) fan-out** (`llmmodeloverlay_controller.go:139-150`)

The watch handler lists ALL overlays and enqueues all of them when any model changes. This works but is wasteful. Should only enqueue overlays whose `spec.baseModel` matches the changed model's `spec.model.name`.

**LLMActiveModelController — no transition cancellation** 

The vllm-proxy has a `transitionCancel` context cancellation pattern (`main.go:1540-1547`). If `spec.modelName` changes mid-transition, the old transition should be cancelled and a new one started. The current controller has no mechanism for this — it just requeues.

**LLMActiveModelController — cache-manager error handling** 

If `CACHE_MANAGER_URL` is set but the service is unreachable, the transition fails hard. Should distinguish between "cache-manager not configured" (skip) and "cache-manager configured but unreachable" (fail/retry).

**LLMBackendController — missing active model tracking** 

The controller doesn't read `llm.cogito.dev/active-model` from Deployment pod template annotations to populate `status.activeModel` and `status.activeModelSince`. This is needed for the operator to know which model each backend is serving without relying on `LLMActiveModel` status.

### 2.2 Deployment Infrastructure Gaps

**Missing ServiceAccount** — `manager.yaml` references `llm-operator-controller-manager` but no ServiceAccount resource exists.

**Missing RoleBinding** — Only a ClusterRole is generated. Need a RoleBinding (namespaced) or ClusterRoleBinding to bind it to the ServiceAccount.

**Missing metrics Service** — The manager exposes metrics on `:8081` but no Service exists to expose it for Prometheus scraping.

**No pod disruption budget** — With `replicas: 2` and leader election, a PDB ensuring 1 replica is good practice.

**No namespace management** — The `manager.yaml` includes a Namespace resource, but the kustomization applies `namespace: llm` to everything. The Namespace should be created separately (or via Flux Kustomization).

### 2.3 Testing Gaps

**No envtest suite** — No `suite_test.go` for envtest-based controller testing.

**No mock cache-manager** — The cache client talks to a real HTTP service. Tests need a test server.

**No unit tests for any controller** — All 4 controllers are untested.

### 2.4 Missing Features

**Migration tool** — `hack/migration/configmap-to-crds.go` is referenced in the Makefile but doesn't exist.

**Prometheus metrics** — No custom metrics for transition duration, success/failure counts, model switch counts.

**Reconcile rate limiting** — No `WithMaxConcurrentReconciles` on any controller.

## 6. Testing Strategy

### Unit tests (envtest)

Every controller gets a `*_test.go` file using controller-runtime's envtest framework:

- **LLMModelController**: Create LLMModel with valid/invalid specs, verify status updates, verify finalizer blocks deletion of active models
- **LLMActiveModelController**: Create LLMActiveModel + LLMModel + LLMBackend, trigger transition, verify Deployment patches, verify status progression. Mock cache-manager with `httptest.NewServer()`. Test transition cancellation by updating `spec.modelName` mid-transition.
- **LLMModelOverlayController**: Create overlay with valid/invalid request defaults, missing base model, verify conditions
- **LLMBackendController**: Create backend with/without matching Deployment, verify phase transitions

### Integration tests (when ready)

- Deploy operator to cluster alongside vllm-proxy (both running)
- Create LLMBackend CRDs matching existing vllm/laguna Deployments
- Create LLMModel CRDs matching existing ConfigMap models
- Create LLMActiveModel and verify the operator's transition logic produces the same Deployment patches as the proxy
- **Do not** activate the operator's transitions until the proxy is decommissioned
